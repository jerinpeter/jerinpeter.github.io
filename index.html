01 · About
that's me,graduation day!

I live at the seam between hardware and software. Hand me a new robot in a crate and I will get it sensing, localizing and navigating, then put the intelligence on top.

Today that means bringing up humanoid and legged platforms at OpenMind and wiring foundation models into real autonomy. Before that I spent years building wheeled robots from the chassis up, published papers about them, and taught ROS to anyone who would sit still long enough.

RTK GPS · NTRIP · ROS

RTK GPS outdoor navigation robot

A large outdoor robot with inflatable tyres and an aluminium extrusion frame that localizes to centimeters using RTK corrections streamed over the internet.

Compute
Raspberry Pi 4 running ROS
Sensors
RPLidar S2, Bosch BNO055 IMU, ArduSimple RTK2B
Corrections
Own base station, Pi Zero W, NTRIP caster
Design
Fusion 360, aluminium extrusion

Overview

Outdoors, the assumptions indoor stacks rely on fall apart: no walls to scan, uneven ground, changing light. This robot pairs low cost hardware with RTK GPS and sensor fusion so it can cross rough terrain and still know where it is to the centimeter.

What I built

  • Designed the chassis in Fusion 360 with inflatable tyres for terrain and an extrusion frame for rigidity.
  • Built an RTK base station whose corrections reach the robot through a Pi Zero W and an NTRIP caster.
  • Fused RTK GPS, IMU and wheel odometry for localization and navigation in ROS.

ACM AIR 2023 · Best Paper Presentation

4WD visual SLAM robot

A four wheel drive ROS robot that builds 2D and 3D maps with RTAB-Map so it can navigate where GPS cannot reach.

Compute
Jetson Nano, Arduino Mega
Sensors
YDLidar X4, Kinect, RealSense T265
Software
ROS, move_base, GMapping, RTAB-Map
Drive
RMCS-2303 drivers, four 100 RPM motors

Overview

Encoders drift and 2D LiDAR has a short reach outdoors. Fusing several sensors and leaning on appearance based mapping gave this robot maps it could trust in places where GPS would not help.

What I built

  • Modeled the robot in Fusion 360 and converted it to URDF for Gazebo.
  • Fused LiDAR, Kinect depth, wheel encoders and T265 tracking odometry.
  • Real time appearance based mapping for robust localization.

Open-RMF · ROS 2 · Nav2

Multi robot fleet navigation

Coordinating a TurtleBot3 fleet with Open-RMF: task allocation, traffic lanes and conflict resolution.

Robots
TurtleBot3 fleet
Framework
Open-RMF, ROS 2, Nav2
Simulation
Gazebo, custom facility map
Tools
RMF web dashboard, RViz

Overview

One robot navigating is a solved problem. Several robots sharing corridors is a scheduling problem. Open-RMF sits above each robot's Nav2 stack and decides who goes, who waits and who reroutes.

What I built

  • A facility map with traffic lanes and delivery endpoints.
  • Namespaced Nav2 stacks for each robot in the fleet.
  • Tasks dispatched from the RMF dashboard, with robots yielding and rerouting to avoid conflicts.

ROS · SQLite · Action server

Multi map navigation with wormholes

Room to room autonomy on the ANSCER AR100: when the goal lives on another map, the robot routes through wormholes.

Robot
ANSCER AR100 AMR
Software
ROS, move_base, custom action server
Data
SQLite wormhole database
Interface
PyQt goal picker

Overview

Big facilities are easier to map room by room, but then a single goal can span several maps. Wormholes are known transition points between maps, so the robot drives to one, swaps maps and carries on, even through a hub room when there is no direct link.

What I built

  • WormholeManager: direct and hub based transitions computed from SQLite.
  • MapSwitcher: swaps map_server maps on the fly.
  • NavigationServer: an action server that chooses direct goals or wormhole routing.

ROS 2 · PyTorch · Reinforcement learning

DQN mecanum navigation

Teaching a mecanum robot to reach goals and dodge obstacles with a Deep Q-Network, built from scratch in ROS 2.

Framework
ROS 2 Humble
Learning
PyTorch DQN, experience replay
Simulation
TurtleSim, then Gazebo
State
Segmented laser scan

Overview

ROS ships with planners, not learners. I built the RL loop myself, proved it on TurtleSim, then moved it to a mecanum robot in Gazebo where the policy has to use sideways motion too.

What I built

  • Validated the reinforcement learning loop in TurtleSim first.
  • Laser scan sectors as state, mecanum velocity commands as actions.
  • A two layer MLP (256 units) trained with epsilon greedy exploration.

ABB plate cleaning arm

Overview

Plates land in random spots, so the arm has to plan for each one: find it, move there smoothly, wipe in a spiral, then transition to the next plate without jerks.

What I built

  • PD control for trajectory tracking with random plate placement.

ROS · Teensy · PID

Mecanum drift control robot

A laser cut, powder coated mecanum platform with custom firmware that turns ROS velocity commands into precise omnidirectional motion.

Compute
Raspberry Pi 4 running ROS
Control
Teensy on a custom PCB, PID
Sensors
RPLidar A1M8, high resolution encoders
Drive
60 RPM Rhino motors, 40 kg-cm

Overview

Mecanum wheels can move in any direction, and they also slip in every direction. Tight wheel control and drift correction are what make the omnidirectional motion actually usable for navigation.

What I built

  • Laser cut metal chassis, powder coated for durability.
  • Teensy firmware converting cmd_vel to PWM with PID and drift correction.
  • A sampling based trajectory planner for autonomous navigation.
